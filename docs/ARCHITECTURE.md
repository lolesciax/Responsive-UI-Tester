# Architecture

Static React application using React Router. Feature modules own pages and interactions. Shared Radix dialog/button primitives provide focus management and consistent styling. Database repository owns writes, validation, transactions, cascading deletion and activity events. Dexie live queries react to local changes. UI preferences and workspace selection use persisted Zustand state. Images are stored as Blobs and displayed through revocable object URLs. Pixel comparisons run in a module worker. ZIP archives contain versioned JSON metadata plus original image binaries; restore validates all records and references before an atomic transaction. No remote data transmission is required.

Navigation metadata lives in `src/app/navigation.ts`, with its presentation in `src/components/layout/Navigation.tsx`. Settings, presets and data management are independently lazy-loaded routes. Screenshot annotation rendering and forms are separate workspace components. E2E helpers live in `tests/helpers/`; all test and tool configuration files are included in strict TypeScript checks. `npm run check` is the shared local/CI entry point.

The browser cannot inspect arbitrary cross-origin DOM, reliably detect iframe refusal, or screenshot arbitrary websites. Live preview is sandboxed and accompanied by an explicit fallback. Manual findings are labeled manual. Optional local automation remains separate.

Preview sandbox policy is centralized in `src/lib/preview-policy.ts`: scripts/forms are allowed with an opaque origin by default. Explicit trust can grant an external site its normal origin and storage; Studio-origin targets cannot opt in. Consent is scoped to an origin and workspace visit, and changing storage mode remounts the iframe. All preview URLs remain validated HTTP(S) URLs without embedded credentials. No top-navigation or popup privileges are granted. Policy reference: [MDN iframe sandbox](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/iframe#sandbox).

`src/lib/preference-storage.ts` wraps both the localStorage property getter and its read/write/remove operations. Denial or quota errors switch preferences to session memory rather than producing rejected persistence operations. IndexedDB failures still show a recovery UI with an option to open Studio directly.

Official setup references reviewed: [Vite](https://vite.dev/guide/), [Tailwind Vite integration](https://tailwindcss.com/docs/installation/using-vite), [Dexie React](https://dexie.org/docs/Tutorial/React), [shadcn Vite integration](https://ui.shadcn.com/docs/installation/vite) and [Rolldown code splitting](https://rolldown.rs/reference/OutputOptions.codeSplitting). `components.json`, TypeScript paths and Vite aliases support extending the local shadcn-style component system.
